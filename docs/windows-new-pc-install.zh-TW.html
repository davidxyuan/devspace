1

填寫設定

只用英文、數字、減號；會轉成小寫。
沒有 D 槽時可用 C:\devspace。
不要加 /mcp 或電腦路徑。
取消 FullAccess 才使用；多路徑以分號分隔。
會開放目前 Windows 帳號能看見的磁碟，並啟用 Hermes 寫入與命令工具。
電腦代號不要和現有的 tyo、oe、home 或其他已上線機器重複。ngrok Token 不要貼到聊天、截圖或公開紀錄中。
2

下載或更新 DevSpace repo

在 Windows PowerShell 執行。若 Git 不存在會先透過 winget 安裝，然後抓取 codex/chatgpt-mcp-router-fix 分支。






3
一鍵安裝 DevSpace + Hermes + Watchdog

  
-InstallTools 會用 winget 補齊 Git、Node.js/npm、Python；ngrok 則直接從官方 latest-stable 下載位置取得 Windows x64 版本。

  
安裝器會把 ngrok 放在 %USERPROFILE%\.devspace\tools\ngrok\<版本>\ngrok.exe，並在建立 Watchdog 前確認它支援 --url 和 --binding。

  

  
安裝失敗可修正原因後重貼同一段。安裝器可重複執行。





4
設定 Hermes 模型與登入

  
Hermes Agent 安裝時會略過互動精靈，因此第一次要執行：

  
hermes setup
hermes status
hermes doctor
hermes -z "請只回答：Hermes OK"

  
找不到 hermes 時，關閉並重開 PowerShell，或執行 %LOCALAPPDATA%\hermes\hermes-agent\venv\Scripts\hermes.exe setup。

故障排除

  
unknown flag: --url
Watchdog 仍使用舊版 ngrok。先更新 repo，再重新執行第 3 步完整安裝；必須保留 -InstallTools，新版安裝器才會下載官方 latest stable 並更新設定路徑。
不要只依賴 winget upgrade ngrok，winget 來源可能仍停留在舊版。

  
127.0.0.1:4040 無法連線
代表 ngrok 沒有成功啟動。先跑一次 Watchdog，再查看 ngrok 錯誤日誌。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.devspace\devspace-watchdog.ps1" -Once -ConfigPath "$env:USERPROFILE\.devspace\devspace-watchdog.config.json"
Get-Content "$env:USERPROFILE\.devspace\devspace-watchdog.log" -Tail 100
Get-Content "$env:USERPROFILE\.devspace\ngrok-watchdog.err.log" -Tail 100

  
公司憑證／TLS 掃描阻擋 ngrok
請 IT 信任 ngrok.exe，或排除 connect.ngrok-agent.com:443 的加密流量掃描。

  
ERR_NGROK_18021
ngrok 帳號同時 endpoint 過多。停止不用的 endpoint 或使用可容納更多 endpoint 的方案。

  
Cloud Endpoint 無法路由
把新機器的 .rule.yml 合併到既有 Traffic Policy 的同一個 on_http_request: 清單，不要建立第二個頂層 key。
